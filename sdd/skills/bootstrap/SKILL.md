# sdd bootstrap

你已装载 **sdd**——需求治理技能系统。它管「一堆事之间谁先谁后、承诺过什么、凭什么算完」：受理、规格、实现、验收、发布、治理记录。sdd 不是知识参考，是行为约束：本文件生效期间，你按下列纪律行动。

## 铁律：先查技能，再行动

只要认为有 **1% 的可能**某个 sdd 技能适用于当前任务，就必须先调用它——在任何响应之前，包括澄清提问、探索代码库、查文件。调用后宣告「Using [skill] to [目的]」，并严格照技能正文执行。

指令优先级：**用户显式指令 > sdd 技能 > 默认行为**。用户一句话可推翻技能；用户没发话时，纪律就是纪律。

## 路由表

| 信号 | 调用 |
|---|---|
| 动作型未分类输入（新需求、想法、变更愿望、文档、插单） | `sdd:intake`（第一响应者，先过三问分流） |
| 写规格、定验收契约、已定稿提案的变更 | `sdd:spec` |
| 写代码、取任务、流水线推进（显式点名提案/任务可直接进入） | `sdd:start` |
| 提案验收、发布 | `sdd:accept` |
| 导出项目知识给外部视角 | `sdd:export` |
| 问进度 / 看板（只读聚合） | 读 `sdd:skills/init/references/governance-files.md` 的看板读法，按 REGISTRY 聚合回答 |
| 建立 / 升级 / 重建治理 | `sdd:init` |
| 会话开始发现治理根 | 先读 `REGISTRY.md` 恢复现场（在途提案 + 其 TASKS.md）；schema 与插件版本不一致：落后 → 可重跑 sdd:init 模板对齐；领先 → 提示 `claude plugin update sdd` |
| 无治理而要推进需求类工作 | `sdd:init`（它对仓库的首次写入必须等你一句确认） |

判断不了归哪个，一律 `sdd:intake`。

## 横切纪律（任何阶段都生效）

- **插单不打断**——当前工作永不因新想法自动转向；新想法在捕获时当场分类：咨询即答，余者入池
- **无任务不写码**——写代码必须挂已定稿提案的任务，或挂判直做的意图
- **开发中推翻已生效方案** → 必记 AMENDMENTS（格式：`sdd:templates/tmpl-amendments.md`；程序：`sdd:skills/init/references/governance-files.md`）
- **提交前必过门禁**（程序：`sdd:skills/start/references/gate.md`——无论何时、谁发起的提交，先读它）
- **治理写入即提交**——standalone 治理仓一笔提交只含一个关注点，状态迁移即时提交，探索、回填等过程性写入在一次响应收口时合为一笔（程序：`sdd:skills/init/references/governance-files.md`）
- **无证据不算完**——验收标准逐条指认证据，指认不出即失败
- **环境变更用户定**——安装全局工具、搭建基础设施，方案摆出来由用户决定，不擅自装
- **行文说人话**——不生造词、不自造缩略语，非必要不用比喻装饰，不为了体系化而行文生涩拗口；对话、文档、提交同一标准

## 常见误区（预判你将用来逃避纪律的借口）

| 你会想 | 事实 |
|---|---|
| 「这只是随口一提/小问题」 | 输入即信号，分类是 sdd:intake 的职责，不是你免检的理由 |
| 「我先看看代码再决定调不调技能」 | 技能告诉你怎么探索；先调技能 |
| 「技能、模板、规则的内容我记得，不用读了」 | 都会演化，读当前版本——治理文档的形状以文件为准，不以记忆为准 |
| 「直接写码最快」 | 无任务不写码；治理链就是最快的那条路，返工才是慢的 |
| 「门禁/流程太重了，这次跳过」 | 这次跳过 = 治理记录从此不可信；要改流程走 sdd:init 升级，不是绕过 |
