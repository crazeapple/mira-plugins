# sdd:intake — 受理、澄清与拆分

一切动作型输入的第一响应者。把模糊意图澄清成清晰边界，拆分为提案——**全过程的留痕只落 JOURNAL**（`[I-XXX]` 澄清与成形，`[P-XXX]` 提案细化）。

## 流程

### 0. 治理检查

无治理根（位置见 sdd:init）→ **退回 sdd:init**，不得自行创建任何文件。

### 1. 分流与捕获

- 插单场景（正在推进其他工作）：**无条件先捕获**——原话逐字入意图池（得 `I-XXX`），回一句「已记录，不打断当前工作」，绝不转向，除非用户明说放下手头
- 常规入口：一眼可判的维护/咨询（「这个 typo 修一下」「这个怎么用」）直接做并回报，不入池；需求与模糊类 → 捕获得 `I-XXX`

### 2. 三问分流

对已捕获意图问三个问题（判据见 `references/triage.md`）：

1. 期望行为与现状有差异吗？
2. 达成方式有方案空间需要收敛吗？
3. 完成标准用户一听就自明吗？

| ①行为差异 | ②方案空间 | ③标准自明 | 判定 |
|---|---|---|---|
| 有 | 有 | — | 进入澄清成形（第 3 步）——方案需要探索 |
| 有 | 无 | 否 | 同上——标准不自明就得有规格 |
| 有 | 无 | 是 | 小改动：直接做并回报，INTENT 区块标已否（备注直做） |
| 无 | — | — | 维护/咨询：直接做并回报 |

### 3. 澄清与成形（JOURNAL `[I-XXX]` 实时落盘）

与用户对话，方法论见 `references/exploring.md`，JOURNAL 条目模板：`sdd:templates/tmpl-journal.md`：

- **边界**：做什么 / 不做什么 / 约束 / 用户语言的成功标准
- **方案成形**：选项摆开 → 选定与否决，**逐条留痕（含否因）**——聊到哪记到哪，不等聊完补记
- INTENT 区块：状态 → 澄清中；边界结论一句话随手更新
- 模糊大需求聊不动 → 停在澄清中，不强行拆分，等后续成熟

### 4. 拆分判定

收敛后判交付物数量（判据见 `references/triage.md`：共享同一验收契约 → 一提案多任务；各自独立验收 → 多提案）：

- JOURNAL 追加 `[I-XXX]` 拆分条目：为何拆、拆成什么
- 建 `proposals/P-XXX/`（1..n，按依赖顺序发号、生成 codename）
- REGISTRY 提案表加行（`intent` 列回指；依赖列登记做环检测——沿非完结依赖游走回自身即环，停下问）；INTENT 区块：状态 → 已拆分，并登记 P 表格（一行一个提案）
- 只拆当前看得清的交付物，其余留池等成熟

### 5. 提案细化探索（按需，逐提案）

提案被推进而技术形态未清时进行，一次只探一个提案：

- **interactive 与用户对话收敛**：选项摆开 → 选定与否决，逐条留痕（含否因），方法论见 `references/exploring.md`
- **unattended 独自收敛**：按已获信息定案
- JOURNAL `[P-XXX]` 实时落盘（候选方案 / 开放问题 / 否决记录 / 形态结论）；完成 = 该提案疑虑清零
- 不推进的提案停在立项——探索不批量预做，日后被推进时重入本步

### 6. 移交

调 `sdd:spec`（逐提案），携带 `I-XXX`——SPEC 的背景与探索素材都在 JOURNAL。**移交前置 = 该提案已细化探索**。探索可重入：spec 定稿检查发现边界不清或方案未定 → 退回本技能，读 JOURNAL 接着上次继续，新结论新条目。

## 常见误区

| 你会想 | 事实 |
|---|---|
| 「澄清内容先记脑子里，聊完一起写 JOURNAL」 | 探索底稿的价值在实时——事后补记必失真；聊到哪记到哪是硬性步骤 |
| 「这个方案否了就不用记了吧」 | 选定与否决**逐条留痕**是流程违规红线；被否备选表来自这些记录 |
| 「这是个小要求，不进池直接做」 | 一眼维护/咨询可以直接做；但凡需要聊的，先捕获得 I-XXX——不捕获，三周后没人记得它被提过 |
| 「正在忙着，这个想法先口头答应」 | 插单不打断：捕获 + 一句话，不承诺、不转向 |
| 「技术方案顺手定了就行，用户看的是结果」 | 走偏多走在「怎么做」而不是「做什么」——interactive 下提案细化探索必须与用户对话，不自行定案 |
