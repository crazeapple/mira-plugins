# exploring.md — 探索方法论

适用于 sdd:intake 的两个阶段：**意图澄清与成形**（`[I-XXX]` 头——边界、约束、方案选定与否决、拆分依据）与**提案细化探索**（`[P-XXX]` 头——针对具体提案的技术方案收窄；按需触发：提案被推进而技术形态未清时进行，一次探一个）。方法同一，落头不同：条目头按书写当时所属实体落，提案不存在前不可能有 P 头，归属模糊宁 I 不 P。interactive 两阶段都与用户对话；unattended 独自收敛。

探索的产物是三样：探索底稿（JOURNAL）、清晰的边界结论（INTENT 区块随手更新）、拆分方案。探索的完成条件：**疑虑清零**——继续问下去问不出新东西了。

## 原则

**自顶向下**——先定问题的边界（解决谁的什么问题、不解决什么），再逐层向下细化方案层次。不在第一轮就钻实现细节。

**先发散后收敛**——每个层次先摆开选项（至少两个，除非真的只有一个），摆完再收。直接收敛 = 把你脑子里第一个想法当成唯一选项；发散不足是返工的第一大来源。

**逐层留痕**——每层讨论有结论就**当场**追加 JOURNAL：摆过的选项、否掉的理由、用户给过的约束原话。**决策必须逐条留痕（选定与否决各一条，含否因）——不留痕即流程违规。**用户说的话也是探索底稿的一部分——约束失忆是下个会话重吵一遍的根源。

## 每层的收敛动作

一层收敛的标志：该层**选项已摆、选择已做、理由已记**。典型层次：

1. 问题边界层：解决什么、明确不解决什么
2. 方案形态层：大体怎么做（选项 → 选定 + 否因）
3. 交付物层：天然分界在哪里 → 拆分判定（一个还是多个提案）
4. 边界细节层：范围轮廓（哪些进来哪些不进来，构成 SPEC 的范围外清单）

## 收敛判据（满足才拆分移交 spec）

- 问题边界一句话说得清（INTENT 区块边界结论就位）
- 方案形态选定且有否因留档
- 拆分判定完成：交付物数量与依据已记 JOURNAL
- 用户在收敛结果上点过头（interactive）；unattended 下按已获信息收敛并在移交时列出全部代用户做的假设

## 与 spec 的交接

拆分后调 sdd:spec。spec 定稿检查若判「边界不清或方案未定」，退回本技能——重入时**不重开**：读 JOURNAL 接着上次的收敛点继续，新结论新条目。
