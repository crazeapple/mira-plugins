# sdd:export — 治理知识导出

把治理文档提炼成**外人可读**的单文件。读者是协作者、上级、新成员——他们不知道也不需要知道 sdd 的存在。

## 流程

### 0. 治理根发现

定位治理根（`<项目根>/.mira/sdd/`）；无治理 → 提示先跑 sdd:init。

### 1. 只读采集

读 REGISTRY + INTENT + JOURNAL + 各提案 SPEC/DESIGN + AMENDMENTS（INTENT/JOURNAL/AMENDMENTS 不存在视为空）。**只读**——本技能除落一个导出文件外不写任何东西。

### 2. 提炼转写

单文件两章（模板见 `references/export.md`）：

- **需求层**（产品/管理视角）：现状与计划——做完了什么、在做什么、计划做什么、为什么转向
- **技术层**（工程视角）：目录结构、技术栈、方案与决策——新人接手需要知道的骨架

**零治理词汇转写**：不出现 P-XXX、I-XXX、codename、状态机、意图、提案等治理术语；以读者关心的问题组织（「项目现在能干什么」），不以治理文档结构组织。演变记录转写为「历程与转向」叙述。

### 3. 落盘

`<项目根>/.export/<项目名>-<YYYYMMDDHHmmss>.md`——时间戳到秒，同名不覆盖。`.export/` 已被 init 写入 `.git/info/exclude`（本地排除）；若发现未排除，提示重跑 sdd:init 补设，**不自行改任何 git 配置**。

### 4. 回报

导出文件路径 + 一句话内容概要。除此之外零副作用。

## 常见误区

| 你会想 | 事实 |
|---|---|
| 「顺手把治理文档也拷一份进去，信息更全」 | 治理信息出治理根 = P7 破防；导出的读者不需要治理词汇 |
| 「导出顺便把 REGISTRY 里过时的状态也修一下」 | 本技能只读；发现文档与实际不符 → 报告，不代修 |
| 「写到 docs/ 里让大家都看到」 | 导出物是派生快照，不是源文档；固定落 .export/ |
