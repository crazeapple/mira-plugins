# export.md — 导出模板与转写纪律

## 单文件两章模板

```markdown
# <项目名> 项目概览

> 导出于 <YYYY-MM-DD HH:mm>，自动生成，快照性质。

## 需求层：现状与计划

### 已完成
<面向使用者的能力描述：项目现在能干什么。一条能力一段，
讲清它解决什么问题，不出现治理编号与状态词>

### 进行中
<正在做什么、进展到哪（用「已可试用/开发中」等读者语言）>

### 计划
<接下来打算做什么（INTENT 成熟项 + 待实现提案的目标转写）>

### 历程与转向
<重要的方向变化及原因——来自 AMENDMENTS 演变链的叙述化：
「最初采用 X，后因 Y 转向 Z」>

## 技术层：结构与决策

### 目录结构
<顶层目录及职责，一棵带注释的树>

### 技术栈
<语言/框架/关键依赖及选型理由（DESIGN 决策表转写）>

### 方案与决策
<关键设计决策：是什么、为什么——被否备选的否因择要保留，
帮新人避开重新踩过的坑>
```

## 转写纪律

1. **零治理词汇**：P-XXX、I-XXX、codename、状态机值（立项/验收中…）、意图、提案、受理——一律转写。对应关系：「提案」→「计划中的功能/工作项」；「意图」→「需求想法」；「完结」→「已上线/已完成」
2. **以读者问题组织**：读者问的是「能干嘛、在干嘛、要干嘛、怎么接手」——不是治理文档的结构
3. **取舍**：内部实现细节不进需求层；需求背景不进技术层。两章各自独立可读
4. **忠实**：只转写治理数据有的；不脑补计划、不美化现状。文档与实际不符处照实写「与计划有出入」
5. **快照声明**：保留文件头导出时间——读者须知这不是活文档
