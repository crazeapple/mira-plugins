# contract.md — 验收标准表

SPEC.md 内的验收标准表是提案的**验收契约**：定稿时冻结结构，accept 按它逐条核验，指认不出证据即失败。表骨架在 `sdd:templates/tmpl-spec.md` 的「验收标准表」节，本文件是列语义与判据的唯一规则源。

## 列规则

- 编号 `A1, A2, …` 提案内递增；TASKS.md 的任务用编号引用覆盖关系
- `结果 / 证据` 两列定稿时留空，accept 阶段填写
- 变更契约 = spec 期内直改 + 提案 version 自增；定稿后（开发中）不许动

## 可核对性判据

一条标准可核对，当且仅当：**能想象出一个明确的动作序列，其结果非黑即白地判定这条标准过/不过**。

| 不可核对（退回） | 可核对（改写方向） |
|---|---|
| 页面要美观 | 首页通过 Lighthouse 可访问性 ≥ 90；配色仅用设计系统 vars.css 中的色板 |
| 性能要明显提升 | 1 万行数据集下，列表渲染 ≤ 200ms（`npm run bench:table`） |
| 支持导出 | 「导出」按钮将当前筛选结果导出为 .csv，字段顺序同表格列序（`e2e/export.spec.ts`） |
| 代码质量要好 | `npm run lint` 零 error；新增文件均有对应测试且 `npm test` 全绿 |

**句式**：主语（具体的界面元素/命令/接口）+ 动作 + 可观测的结果 + （阈值/精确形态）。

## 验证绑定规则

- 每条标准绑定**一条可独立执行的命令**（含工作目录约定），accept 时逐条运行；命令必须此刻真实存在或在本提案 TASKS 内被创建——引用不存在的工具 = 不可核对。UI 行为的命令就是 E2E 测试，用例在本提案 TASKS 内建出
- 「需真机 / 需视觉判断 / 需外部账号」不是绑定形式——写出可自动核对的等价断言（测试账号、设备仿真、E2E 断言）；写不出 = 不可核对，退回重写
- 每条验收标准至少被一个任务覆盖；每条绑定只属于一个标准（复用命令可以，证据逐标准指认）

## 证据指认规则（accept 用）

每条标准核验后在行内填：结果（过/败）+ 证据（命令名、关键输出摘要、用例名）。**指认不出 = 败**——「应该过了」「看起来没问题」不是证据。
