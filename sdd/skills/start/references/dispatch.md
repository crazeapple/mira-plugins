# dispatch.md — 提案派发、回收核验与中断恢复

提案级派发是 sdd:start 的默认推进形态：主会话领到提案即派发一个子 Agent，在其 worktree 内按 TASKS 序完成实现；主会话交付判断（治理回填、核验、上报转呈），子 Agent 只交付提交。并行加速（任务级 / 多提案同时）仅在**用户明确要求**时使用；没有要求的并行 = 违规。

## 派发粒度

- **提案级（默认）**：一个待实现提案一个子 Agent，在其 worktree 内按 TASKS 序完成全部任务
- **任务级（点名）**：同提案内无依赖的任务分给多个子 Agent 并行
- **多提案级（点名）**：多个待实现提案各派一个子 Agent 同时推进（各建各的 `dev/<codename>` worktree，天然隔离）

## 派发简报（每个子 Agent 必须拿到）

1. **提案上下文**：P-XXX 三文件路径——SPEC（契约表，任务覆盖列的依据）、DESIGN（技术决策）、TASKS（任务清单与顺序）
2. **工作区**：worktree 路径 + 分支名（主会话已建好，子 Agent 不建不删分支）
3. **实现纪律**：按 TASKS 序、任务间不停顿；一个任务一个提交、单提交不混多任务；提交信息公开面零治理（主题行无治理 ID、无 footer）；提交前过门禁（附 gate.md 路径）；E2E 用例随任务创建；照常自检——正式验证闸门只有提案末端一道，不在此跑
4. **边界**：只做本提案任务；发现设计问题**停下上报，不就地改设计**；不碰治理记录（TASKS 完成列、REGISTRY 由主会话回填）
5. **完成回报格式**：逐任务一行「任务号 → commit hash」+ 自检结果 + 疑点清单（无则写无）

任务级派发用同一简报，范围收窄为单任务及其覆盖条目、相关决策。

## 回收核验（逐项，不抽检）

1. 提交存在且一任务一提交；`git log` 主题行零治理信息
2. 改动范围与 TASKS 任务内容吻合（无越界文件）
3. 门禁清单主会话复核
4. 上报的设计疑点转呈用户；若走放弃流程，程序在 `git-flow.md`「放弃」节
5. TASKS.md 完成列、REGISTRY 状态由主会话统一回填（子 Agent 不直接改治理记录）

任一项不过：退回重做（重新派发，附核验发现）或主会话接手修复——**不带着问题进入移交**。

## 中断恢复

子 Agent 中途终止（无完成回报，dev 分支有部分提交）的续跑程序：

1. **先回收**：`git log` 比对 TASKS——已有提交的任务即算完成，完成列照常回填
2. **再派发**：新简报附「已完成任务清单（勿重做）」；子 Agent 接序做剩余任务，动工前先核对目标任务的提交是否已存在（先查再补，中断重派不重复实现）
3. 同一提案派发连续两次中断 → 主会话按同一纪律直做（程序不变）
